## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

- Front-page system map: layout and chain (causes/effects) logic live in src/lib/system-map.ts as pure functions so they stay unit-testable.
- The router must derive its basepath from the build's base URL (import.meta.env.BASE_URL): the app is also served from a sub-path (GitHub Pages), and without it that host renders only a 404.
- Combined Supabase+Neon dataset (map, themes, timelines) lives in src/data/murros-data.json (bundled import via src/lib/murros-data.ts; a copy also goes to public/data/), regenerated by scripts/build-murros-data.py (Neon part comes from a pre-fetched query dump) so the map and the static GitHub Pages build work without any database connection.
- Cause-and-effect views (front-page map, Tutka, Pallo) use `data.causal` from src/lib/murros-data.ts, not `data.edges`: only cause-type relations that run forward in time (`isCausal` in src/lib/system-map.ts). Similarity, contrast and example relations stay in `data.edges` and must not be presented as causes or effects. The front-page chain shows direct links by default; deeper steps are opt-in.
- Statistical series are filtered by `usableSeries` (≥ 5 observations, not constant). A phenomenon shows only the series hand-picked in src/lib/node-series.ts (the series must measure the phenomenon itself). Never show series through the text-matched conclusion links in the dataset: they produce nonsense pairings.
- The "lampokartta" route counts recorded phenomena per cell and must be presented as the dataset's coverage, not as the strength of change. Theme curves on /teemat are editorial assessments from a fixed six-stage model, not measurements.
- The GitHub Pages build (mode "pages") mounts into <div id="root">, so RootShell must not render <html>/<body> in that mode (it froze input events).
- /poikkeamat ("laboratory values"): indicators come from Supabase (public key, no secrets) and, for series Supabase lacks (living alone 15fi/12c6; fertility by birth order 12dm, mean age at first birth 14lg, births outside marriage 12dk; temporary jobs 12bt and young adults' studying/NEET 13am; tertiary education by sex 12bq), straight from Statistics Finland's PxWeb API, via scripts/build-indicators.py into src/data/indicators.json. Reference ranges, episodes and explanations are pure functions in src/lib/anomaly.ts. Every range must show its basis (agreed limit, Nordic corridor, or Finland's own history 5–95 %); trending series are judged by year-on-year change. Only events in `CONFIRMED` are shown as confirmed explanations; same-life-area events are "candidates" and other-area events are "samaan aikaan", never presented as causes. New routes must also be added to the route list in .github/workflows/static.yml.
- Proposed additions to the map's Supabase data (items/relations) are written as reviewable files under docs/ (e.g. docs/ehdotus-yksin-asuminen.md, docs/ehdotus-perhepolitiikka.md) for the user to apply through Lovable; this repo cannot write to Supabase.
- Order-specific fertility is computed in scripts/build-indicators.py from StatFin births (12dm) and women by age (12c6); the script exits if the computed total differs from the official TFR (12dt) by more than 0.03.
- Supabase series that stop before the latest year (unemployment, employment rate, Gini, real wages, CO₂ per capita, homicides, TFR) are extended in scripts/build-indicators.py with official StatFin data via `splice()`, which exits if the overlapping years differ more than the stated tolerance. Prisoners per 100 000, private credit / GDP and under-5 mortality are not extended: no open StatFin source, or (under-5) small annual counts would create false anomalies.
- Young adults: "Nuorten aikuisten osuus väestöstä" (StatFin 11rc, 1865–) and "Työttömyys 25–29 suhteessa kaikkiin" (ratio of the 25–29 to the 15–74 unemployment rate). The ratio's 1963–1988 values are transcribed by hand in scripts/build-indicators.py (`LFS_1993`) from Statistics Finland, Työvoimatilasto 1993:7, table 8; 1989–2008 come from the archived StatFin table 11pl and 2009– from 13aj. The series has a break in 1989 (the 1993 publication gives ratios about 0.1–0.2 higher for 1989–1991), so a dip at 1989–1990 is partly a method change.
- /elamankaari (life course): shares of each one-year age group (15–45) by family position (StatFin 12c6, 1992–) and main activity (115c, 1987–), built by scripts/build-lifecourse.py into src/data/lifecourse.json; transition ages (50 % crossing, 20 % for studying, peak age) are pure functions in src/lib/lifecourse.ts. These are yearly cross-sections, not cohorts. In 115c, under-18s are classified as students from 2005, so 15–17 employment shows as zero (a classification change).
- /selitykset (explanation ledger): one phenomenon, competing explanations side by side, each with what it would predict, what was observed and a verdict (sopii / osittain / ei yksin / ei testattu), ordered by evidence. Content lives in src/lib/selitykset.ts; charts read src/data/indicators.json and src/data/nordic-tfr.json (Eurostat demo_find, scripts/build-nordic-tfr.py), and src/lib/selitykset.test.ts checks that every number quoted in the text matches the data. The birth-order split is labelled bookkeeping, not a cause. Untested explanations stay visible as "ei testattu", never dropped.
- The /selitykset page opens with an animated timeline (src/components/ExplanationTimeline.tsx): the fertility curves draw year by year and each explanation's verdict appears at the year of the observation that tests it (`beats` in src/lib/selitykset.ts; tests require every explanation to have a beat). The animation pauses at each new verdict, respects prefers-reduced-motion (steps a year at a time) and starts in its finished state so the page is readable without playing it.
